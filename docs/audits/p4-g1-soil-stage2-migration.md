**`validate()` rejects, on import:**
- a static cell on a date-dependent context;
- an unknown selector;
- selector cells ≠ {inside, outside};
- an approval that is not `true`;
- a leftover `reason`;
- a date-dependent context relabelled as static `APPLIED`.

**`getVol10JieshaRuntime(month, pillar, activity, civilDate?)`:**
- throws when a date-dependent context has no date;
- the selector throws for unsupported dates;
- otherwise it returns `{status: 'APPLIED', cell, selector, soilState}`, so `vol10JieshaCell` and scoring are unchanged.

**Unchanged:**
- `thoVuongDungSu.ts` (the product god keeps using it);
- the scoring algorithm, the P4 adapter, `NORM` and `canonical-v1`;
- the 11 static demolition contexts and all G2 cells;
- the `resolveVol10` item shape (no new field reaches activity or event output).

The architecture follows the ruling: calendar fact (rule service) → authority selector (v4 + registry) → scoring (unchanged). There is no astronomy in the JSON, the resolver branches or scoring.

**Date-range safety.** Production builds the classical day only in `almanac.ts`, and events pass their own date. The app is limited to 1900–2100 (`MIN_YEAR` / `MAX_YEAR`, `range.ts`, the date pickers, and `groupA` / `groupB` throwing outside), which is exactly the rule's range. The full-range forward dump calls every day and every event with 0 throws.
