## 6. Fail-loud semantics

The only runtime files changed are `xiejiVol10JieshaAuthority.ts` and `xiejiVol10Resolution.ts`.

**`validate()` rejects on import:**
- an excluded context with a cell (avoid or blank);
- an excluded context relabelled `APPLIED`;
- an excluded context with production or authority approved, or without a reason or debt;
- an APPLIED context without a cell, with a cell that differs from its coverage `cell`, or with any approval not `true`;
- a context key set ≠ the 16 contexts;
- any unknown status;
- count drift.

**`getVol10JieshaRuntime`** returns `{status: EXCLUDED_PENDING_DATE_DEPENDENT_AUTHORITY, reason}` for an excluded context **without reading the cell table**. A missing context throws.

**`vol10JieshaCell(runtime)`** is the only way to read a cell. It throws for any state that is not `APPLIED`. `resolveVol10` derives `kept` only through it.

**Two separate paths, tested separately:**
1. Authority access on an excluded context throws.
2. Normal evaluation keeps the approved legacy output (`no_annotation`, Kiếp Sát informational, `authorityExclusion` naming the new status). It does so because the context is excluded, not because a cell exists.

**Reachability ≠ applicability.**
- Demolition reaches 劫煞 in all 16 contexts and is applied in exactly 11.
- No heading alias touches 壞/壊.
- Stage 2 finding: `NORM 壞→壊` is **not** what makes demolition reachable under 劫煞. The 劫煞 list and the activity map both read 破屋**壞**垣, so the match holds without the fold.
- `NORM` **is** load-bearing for the P4 canonical key (`canonicalP4HeadingKey`, G1-b `canonical-v1`), and it is pinned. The `norm_fold_removed` mutant is killed by the reachability test.
- The bypasses of context coverage are tested directly:
  - resolver reach without the authority consult;
  - a demolition alias;
  - a self-consistent promotion of an excluded context. That one passes `validate()` and is caught by the pinned 395 + 5 access set and the v3 generator verify in `ci:p4`, not at load.

## 12. G1-b protection

**Production.** The G1-b production state (`canonical-v1`) is unaffected: 2025–2027 delta 0 (§7). The 5 witnesses stay `only_ji / 20 / avoid`, asserted forward and rollback in the Stage 2 test.

**Finding during the gates.**
- The full G1-b domain gate (`p4MigrationDiffV3.test.ts`, `P4_MIGRATION_V3_FULL=1`) measures `source-key-v1` → `canonical-v1` on the *current* graph.
- With authority v3 loaded it counted **342** changed demolition days, not the frozen 353.
- Cause: the counterfactual `source-key-v1` side leaves demolition `baseline` on P4 days, which sends it down the vol10 path, where 劫煞's avoid cell now applies.
- **Exact measurement** (`g1b-counterfactual.json`; computed in `ci:p4` with `G1GS2_G1B=1`, frozen in the Stage 2 test). `source-key-v1` on v3 vs v2 differs on **15** domain days:
  - they are exactly the 15 2025–2027 scope dates of the 11 APPLIED contexts;
  - every one is −15, with Kiếp Sát going `informational:no_annotation` → `applied:avoid`;
  - by context: 辰乙巳 1, 辰己巳 3, 辰辛巳 1, 未丙申 3, 戌乙亥 3, 戌癸亥 3, 戌丁亥 1;
  - status: 4 neutral→watch and 11 watch→avoid; 0 hard-warning changes.
- 353 − 342 = 11 is only the net effect on the G1-b two-mode comparison. The per-day measurement above is the exact delta.
- The sampled `npm test` run (every 10th date) did not hit those days. Only the full gate did.

**Resolution (owner decision required; see the final report).**
- The 353 / 320 / 337 / 0 envelope is G1-b history, measured under authority v2.
- The file's graph is now pinned to authority v2 (`g1GlyphRollback.ts`, id asserted), following G2's `c82b681`. Its Golden-anchored pre-G2 proof stays on v1 (id asserted).
- The full gate passes 11/11 with **353 / 320 / 337 / 0** and the 5 witnesses.
- No expected value or G1-b artifact changed.

**Consequence for rollback.** Rolling back G1-b alone (`source-key-v1`) on top of authority v3 is no longer byte-identical to pre-G1-b output on those 15 days. The supported rollback order is G1 glyph first (authority v2), then G1-b. This is recorded in §20.
